# ADR-0006：独立的程序化资产循环入口

日期：2026-09-28。状态：已接受。

## 背景

普通技能服务网页游戏切片，用户另需对照标杆、独立严审、未达 WOW 持续改进的
资产生产入口。将严格长循环作为普通技能的默认路径，会扩大普通任务范围。
Gauntlet 现有独立资产模式绑定 Blender/Three.js，不宜把它们的工具契约直接套在
本项目的 2D 烘焙接口上。调研依据见 `../research/asset-loop-landscape.md`。

## 决定

1. 新增 `procedural-game-assets-loop`，首版聚焦可复现的 2D 程序化资产。
   普通入口仍服务网页游戏；新入口不要求玩法、Godot 或 Blender。
2. 使用本项目合同 `pga-loop/1`：总控不制作或自审；builder 不裁决；视觉 critic
   先盲比封存、后揭盲全量评审；交付 critic 独立运行最小消费验证。同一冻结候选
   必须在两个不同完整批次中全部 WOW。任何缺失、污染、候选改变均不能复用旧通过。
3. 无默认轮数、时间、token 或费用上限。它是继续改进策略，不是无限资源承诺或
   新服务扣费授权。用户停止、宿主限制、真实能力/输入阻塞分别保存状态；不能以
   “无限”绕开工具硬停，也不能把中断标成完成。
4. 按用户明确要求，材料约束采用独立上下文、白名单与“不许读其他材料”的指令，
   不强制操作系统隔离或哨兵探测；共享目录不阻塞正式评审。同上下文换角色无效，
   实际越界读取或泄题使本次评审作废。`private/` 不是访问控制，报告如实标为
   指令级约束。无独立子代理能力时可转交独立任务包，不强依赖某一代理 API。
5. 资产源码是实现依据，参考图不是贴图捷径；新配方或渲染器可按需求扩展，但需
   保持 ADR-0001/0004 的纯核心与共享烘焙边界。不把“程序化”作为视觉降标理由。
6. 一个工具包开发源、两个自包含技能载荷。`tools/release.mjs --skill <入口名>`
   使用同一清单与打包实现。新入口无需依赖用户已安装的旧普通版或 Gauntlet；
   只借鉴方法，不宣称 Gauntlet 的正式兼容。辅助脚本只核验记录与文件，不判断审美
   或提供操作系统沙箱，也不是后台调度器。

## 后果与取舍

- 多一份派生载荷换取独立搬运、安装和版本验证；不维护第二套核心代码。
- 指令级材料约束适用于共享工作区，代价是依赖 critic 遵守指令；不把它冒充安全隔离。
- 相对偏好、图像差分与数值评分均只作证据，不能独自定义 WOW。
- 先确认质量、尺寸与范围，再冻结判据；不能在无限循环中偷偷减帧、缩图或删支柱。
- 本阶段不建设通用代理调度服务或承诺自动收敛；未达标的真实试验仍可支持维护决策。
