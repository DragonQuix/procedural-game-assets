# 视觉质量标准：同级质量与整体美学

本标准用于程序化资产及其实际游戏画面。标杆提供质量标尺，不是待复制的答案。
不把程序化实现、已经进步或测试全绿作为降低美术要求的理由。

术语与实现边界见 [CONTEXT](../CONTEXT.md)、[ADR-0001](adr/0001-platform-decoupling.md)、
[ADR-0004](adr/0004-web-first-integration.md) 和 [ADR-0005](adr/0005-canvas-template.md)。
评审标准不改变核心/IO 分层，也不要求额外搭建引擎或超出当前任务范围。

## 先确定评价依据

制作前在现有任务说明或验收记录中简短写明以下内容，不另建复杂状态系统：

| 内容 | 要确定什么 |
|---|---|
| 用途与范围 | 资产类型、目标显示尺寸、使用背景、关键游戏状态、必要动作与变体 |
| 质量标尺 | 有标杆时实际看原图，说明其整体吸引力、设计组织和完成度体现在哪里 |
| 设计约束 | 用户明确要求的题材、风格、必要特征与功能，不从图片自动继承角色身份 |
| 原创空间 | 未被约束的造型、配色、姿势、服饰、材质表达和细节组织 |

有标杆时，默认目标是约定用途内的**质量同级**，不是轮廓重合、同色或同一角色。
同风格也不等于同设计。只问会影响结果且尚不明确的问题，不让用户重复确认已有要求。
原图默认只读，不能把参考裁切成贴图或逐像素编码冒充程序化创作；用户授权的参考纹理
须单列来源和使用范围，不能默认为所有图片都允许直接使用。

没有标杆时，以用户要求和事先确定的风格样本/质量目标验收，不强制用户补图，不套用
工具包演示作为质量上限，不编造“已达标杆同级”。样本和目标必须在批量制作前确定，
不能事后选择一个较差样本来证明当前结果合格。

每个检查项区分“参考可支持的比较”与“任务独立要求”。静态参考不能证明动画标准，
角色立绘不能自动代表整张游戏场景；缺少这些参考不自动阻塞任务，但必须按已对齐的
动作、场景和使用要求另行验证。若参考明显不支持用户要求的质量或尺度，先澄清差距。

## 评审范围：先整体，再局部，再回到使用场景

| 范围 | 判断准则 | 证据 |
|---|---|---|
| 整体美学 | 完整、协调、有吸引力；主次明确、气质统一，达到当前任务的成熟度而非拼凑或占位感 | 正常显示尺寸的完整资产及游戏画面，先于放大图 |
| 设计组织 | 轮廓、比例、姿态、体块与负空间共同表达功能和性格，不要求与参考几何一致 | 完整主体，必要时剪影辅助 |
| 色彩与层级 | 明度、色相、饱和度、焦点、疏密和留白受控；玩家/危险/背景权重符合游戏意图 | 原色画面，灰度只作诊断 |
| 表现完成度 | 像素簇或线条、边缘、体积、材质、光影和细节干净且自洽 | 原生尺寸与适度放大图 |
| 实际使用 | 目标尺寸下清楚稳定；人物、地形、交互、危险与 HUD 互不妨碍，关键状态易识别 | 实际背景、典型交互状态、原尺寸/常用放大/非整数缩放与窄屏 |
| 系列与整场景 | 资产尺度、表现语言和完成度一致；整体构图、前后景、HUD 字体/布局与反馈协调 | 整套资产、完整游戏截图及实际播放，不只看最佳单图 |

完整游戏截图的质量不能由角色画廊代替，精致角色也不能抵消粗糙场景或遮挡画面的 HUD。
若任务仅为单项资产，不增加无关 UI、关卡或完整游戏的交付要求。

按实际资产类型增加检查，不对所有任务强加同一清单：

| 类型 | 增补范围 |
|---|---|
| 角色/生物 | 性格、姿态与重心、装备关系，多方向时的设计一致性 |
| 道具/图标 | 功能识别、视觉重量、系列区分度与统一性 |
| 地形/植被 | 拼接效果、重复痕迹、边界过渡、疏密变化与前后景层次 |
| 特效 | 信息重点、形态演化、强弱节奏、时序层级及是否遮挡关键内容 |
| 动画 | 实际播放的意图、重量感和节奏；接地、漂移、跨帧一致性及循环接缝 |

覆盖约定的资产类别、关键动作和游戏状态；随机变体使用预先选定的代表性种子，注明
未覆盖项，不临时挑好看的样本。动画必须看播放，静态拼图仅辅助定位问题。

## 判据：不把偏好、相似度或分数当作质量

整体及参考支持的必需维度分别使用以下关系：

| 关系 | 含义 |
|---|---|
| `BELOW` | 有影响整体观感、专业完成度或实际使用的实质质量差距，需要返修 |
| `ON_PAR` | 在约定用途与方向内具备同档吸引力、设计控制力和完成度，允许次要强弱与设计选择不同 |
| `ABOVE` | 满足同级要求并有可说明的额外优势；不是必须超过标杆才能交付 |
| `NOT_COMPARABLE` | 材料、尺度、用途或参考覆盖不足，不能可靠比较；补证或澄清，不盲目返修 |

无标杆或参考不覆盖的维度，按独立要求记录 `PASS / NOT_YET / UNVERIFIED`，不伪造等级
关系。普通版视觉总评也使用这三种状态，并与功能/技术结果分开汇报。

整体美学必须单独判断：这是设计完整、处理成熟、符合约定质量的正式画面，还是只有
零件正确？细项合格但整体散乱、僵硬或平庸，仍可不通过。证据可以指向整个主体或
全场景的视觉关系，不必把整体感受强拆成像素坐标。

整体否决仍须说明可见现象及其影响。个人不喜欢某种题材、颜色或风格不构成缺陷。
不要求每个细节都不弱于标杆，但某项明显降档不能靠其他优点、平均分或技术测试抵消。

- 颜色、服饰或轮廓不同但设计关系成立：属于允许差异，不报“身份不像”。
- 纹理更少但形体、材质概括与层次成熟：不能因简洁而判低一档。
- 外观相似但比例僵硬、颜色浑浊或重点分散：不能因相似而放行。
- 粒子更多、辉光更亮或装饰更多：不自动提高等级；妨碍可读性时反而应返修。

不使用总分门槛、像素相似度、SSIM、颜色数量、细节密度或来源猜测作为美学通过条件。
像素哈希可验证确定性与技术回归，不能证明好看；“已比上一版好”也不能代替当前目标。

## 对照条件与返修

先看完整正常尺寸画面并记录整体印象，再检查细部，最后回到游戏场景复核。
参考对照应保持用途、显示条件和信息量可比，不强求原创设计同姿势、同几何或同构图。
保留原生视图与实际显示视图，不扭曲比例、不美化参考、不靠缩小参考或展示板包装藏缺陷。
自身前后版本做回归比较时固定状态、种子、tick 和视图；该规则不等于要求模仿参考姿态。

按“影响质量等级或使用的整体问题 → 支撑它的形色/动作关系 → 局部完成度”返修，
优先次序由可见问题决定，不机械地每次从轮廓开始，也不默认靠加细节解决问题。
保留需保护的优点，完成修改后复看整体和关键状态，避免局部改好但全局退步。

有效意见应包含：范围/维度、现象、影响、参考依据或独立要求、证据、严重度和复查方式。
例如：“头部与背包都是最强对比，主识别区域被分散；需重组明度重点，在实际尺寸下
优先看清主识别区域，不要求换成标杆配色。”不能只写“再高级一点”或指定复制参考解法。

`BLOCKER` 为关键要求/功能失败或证据失真，`MAJOR` 为实质降档或明显影响使用，
`MINOR` 为不影响目标等级与用途的局部瑕疵。更高追求另列建议，不将其变成隐含要求。
无法看图、无法播放或缺关键材料记 `UNVERIFIED`，不能把未知伪装成通过或已证实的低质量。

## 普通版的轻量验收与交付

在现有验收记录中保存一张简表或短段落即可，不要求宪章 JSON、匿名封存、双批次或无限循环：

- 评价依据：参考与质量标尺，或无标杆时的独立目标；明确约束及原创空间。
- 覆盖与证据：检查了哪些资产、动作、游戏状态、尺寸和背景，哪些尚未验证。
- 结论：整体美学单独结论；有依据时的等级关系；各必需维度、功能/技术检查分别记录。
- 问题与处理：严重度、证据、返修方向、复查结果及不阻塞的建议。
- 评审来源：制作代理自审、独立代理或人工；没有独立评审不能自行改称独立通过。

视觉 `PASS` 要求整体美学通过、所有必需维度和明确约束满足、关键范围已检查、无未解决
的 `BLOCKER`/`MAJOR`，且每个 `MINOR` 明确不影响目标。要求参考同级的部分必须为 `ON_PAR`
或 `ABOVE`；`NOT_COMPARABLE` 不是通过。参考未覆盖的内容按事先明确的独立要求验证。
已有证据表明不达标时记 `NOT_YET`；尚缺必要证据时记 `UNVERIFIED`，分别说明问题与缺口。

技术与玩法验收仍独立进行，整体游戏完成须同时满足用户要求。可修问题在当前任务范围内
修复；受时间、工具或信息限制时如实交付差距，不宣称视觉已通过。普通版不默认新增预算
上限，也不承诺无限打磨。只有用户明确要求严格独立循环时，才转向循环版，且不得把普通版
的 `PASS` 当作循环版 WOW 或复用其裁决。
