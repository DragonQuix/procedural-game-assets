# 程序化游戏资产循环版

目标是美观、专业、可复现且可直接消费的资产，不是“能画出来”或“测试全绿”。
标杆用于比较整体吸引力、设计控制力与完成度，不默认继承角色身份、几何、配色或姿态。
本入口采用 Gauntlet 方法，执行本包自包含的 `pga-loop/2` 合同；无需安装 Gauntlet。
它不是后台服务，不承诺收敛或会话结束后自动运行。

## 启动

1. 将本文件所在目录解析为 `SKILL_ROOT`，工具根为 `assets/toolkit/`，要求 Node 22+。
   先读 [对齐与标杆处理](references/alignment.md) 和 [视觉范围与准则](references/visual-quality.md)，
   实际看用户原图，不只读文件名。质量标尺、明确设计约束与原创空间分别记录。
2. 当前授权工作区中建立独立 `RUN_DIR`；已有同一任务的检查点则先核对执行所有权，
   不另起循环或清除历史。旧 `pga-loop/1` 按 [兼容说明](references/tooling.md) 只读验证，
   升级需确认新宪章、新候选并重评，旧 WOW 不继承。原图、技能安装、其他项目默认只读。
3. 探测可执行生成器、实际读图与独立子代理。记录阶段白名单和明确的禁止读取指令；
   默认靠独立上下文与指令约束材料，不要求文件沙箱或哨兵访问测试。
4. 给用户简短说明标杆覆盖/盲区、交付范围、评审维度与未覆盖项。有关键歧义先问；
   用户确认宪章后开跑。用户明确允许按建议自主对齐时可免等待，仍保存方案。

## 角色与循环

先读 [循环与恢复](references/loop.md) 和 [辅助脚本合同](references/tooling.md)。

- 总控：对齐、冻结宪章、派任务、独立采集、封存记录、分诊与恢复；不兼任 builder/critic。
- builder：只改授权的源码、配方、参数与文档，不自评通过；多个 builder 明确文件所有权。
- visual：全新上下文，先仅接收 [盲比任务书](references/critic-blind.md) 与无来源图，
  先看整体，分开质量判断和个人偏好；封存后才给 [视觉任务书](references/critic-visual.md)、
  视觉准则、标杆、宪章和客观证据，复查全部范围与约束，不强制猜来源。
- delivery：另一全新上下文，只接收 [交付任务书](references/critic-delivery.md)、冻结交付包、
  正式使用说明和宪章，亲自复现生成与最小消费。不得收到制作叙事或历史成绩。

每轮：制作 → 固定条件重建/采集 → 技术预检 → 冻结候选 → 独立评审 → 分诊返修。
每个新批次使用新的 critic 上下文；总控不得继承完整聊天给 critic。
Codex 可用 `fork_turns="none"`，并明确告知不许读取白名单外材料、制作历史或来源映射。
共享文件系统不阻塞正式评审；如实记录这是指令级约束，不宣称操作系统安全隔离。
若实际发现越界读取、继承制作历史或提前泄题，该次裁决作废，另派干净上下文。

## WOW 准出

视觉与交付各有否决权。视觉必须单独通过整体美学，整体与标杆可支持的必需维度达到
`ON_PAR / ABOVE`；参考未覆盖部分满足冻结的独立要求，全部范围/视图与明确约束已审。
全部支柱达标、技术门禁通过、无 BLOCKER/MAJOR、没有可复核回归。同一未修改候选
必须获得两个不同、完整评审批次的全部 WOW。WOW 是高质量准出标签，不要求超越标杆。
偏好选中候选、猜不出来源、总分高、单批次通过，都不是最终准出。
视觉分数仅作诊断；整体否决须说明可见现象与影响，不能把风格差异或个人偏好当缺陷。
静态标杆不证明动画质量，实际播放按已对齐的动态要求验证；缺材料不能伪装成低质量或通过。

缺省 `maxRounds / maxMinutes / maxCost = null`，不自行加上限，不按成本降标。
无上限不授权安装、上传参考图、付费服务、额外购买或后台任务。若用户明确授权某
收费渠道但未设限，按该授权执行并如实记账；账单未知记 unknown，不估作零。
用户暂停/取消、宿主硬限制、不可解的参考盲区、路线不适建分别保存检查点，报告
当前差距而非完成。只有用户恢复指令可解除用户暂停/取消状态。

## 工具包使用边界

- 复用 `assets/toolkit/src/` 的纯绘制/几何/烘焙与 IO 适配，不重新发明导出器。
  现有配方只是起点，不是美术质量上限；需要新能力就扩展运行目录内的源码。
- 阅读工具包 `CONTEXT.md`、`docs/recipe-guide.md` 及 ADR-0001/0002/0004/0006/0007；
  当前没有 `CONTEXT-MAP.md`。给 builder 的任务书必须引用它们作为术语与边界来源。
- 从技能复制工具包到运行目录后先校验发行清单；发行副本保持只读，用户配方/新模块
  放自己的源码目录。确需改工具包时另建可修改副本，记录差异，不重写发行清单掩盖修改。
- 交付程序、配方、种子、可调参数、运行步骤及约定的 RGBA/PNG/图集/预览。
  不强制搭完整游戏。资产生成与网页启动烘焙仍共享实现；动画不能仅凭静态拼图验收。
- 原图裁切/测量只作参考与对照，不允许嵌入原图、逐像素描摹编码或贴图伪装成程序化重建。
  若用户明确授权参考纹理，宪章逐项登记并区分程序化部分，不能默认偷换实现路线。

## 交付汇报

展示实际候选预览；列出是否 WOW、当前 candidateId、两个 reviewId、每个角色的
裁决与遗留项、整体美学/质量等级、覆盖情况、交付目录和重建命令。
中断时写清状态、缺什么、下一步以及恢复方法。
机器脚本通过只证明结构与哈希一致，不证明画面优美、评审真实独立或已人工试玩。
