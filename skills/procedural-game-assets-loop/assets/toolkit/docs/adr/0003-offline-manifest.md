# ADR-0003：离线清单契约——版本化 JSON + 稳定产物

日期：2026-09-26。状态：已接受。

## 背景

工具包的首要消费方式是离线导出 PNG 图集 + JSON 清单（Godot、Canvas 只消费产物，不重写生成器）。如果清单格式不稳定或混入环境信息，下游导入会以难以排查的方式损坏。

## 决定

1. `AssetManifest` 必备字段：`schemaVersion`、`generatorVersion`、`recipeVersion`、`seed`、`pages`、`frames`、`clips`、`provenance`。
2. 帧的图集矩形与未裁剪源尺寸分别记录；锚点、附件点、剪辑帧序列与毫秒时长全部入清单。
3. 文件名稳定、帧 ID 唯一；清单不含构建时间戳、不含开发机绝对路径。
4. `schemaVersion` 不兼容时导入必须失败并说明原因，不静默猜测；向后兼容的增补只升小版本。
5. 跨平台一致性判据：解码后的 RGBA 与语义元数据一致；PNG 字节级一致只在锁定编码器版本时要求。
6. 图集首版：稳定排序的简单打包、不透明裁边不启用、不旋转打包；支持页面最大尺寸、透明边距与多页。消费建议（nearest 过滤、禁 mipmap）写入清单或适配说明。

## 后果

- 导出器与导入器分别可测：必须能把图集按清单切回帧并与烘焙结果逐像素比较。
- 工具版本与 schema 版本解耦：API 变化不必然升 schema，清单不兼容变化必须升。

## 备选方案（已否决）

- 把元数据塞进 PNG 文本块：不利于版本控制 diff，Godot 侧读取也更绕。
