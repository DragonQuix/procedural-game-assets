# ADR-0004：网页优先接入——启动烘焙与离线导出共享烘焙核心

日期：2026-09-26。状态：已接受（取代原方案"PNG 图集为首要消费方式"的排序）。

## 背景

原方案把"离线 PNG 图集 + manifest，Godot 优先消费"列为首版必做。范围校正后，
首要目标是让 Agent 制作**网页游戏**：原项目（others_003）的模式就是
"启动时程序化生成并预烘焙，运行时只 drawImage"，不依赖任何导出文件。
此前已完成的离线导出能力（P3）依然有效，但只是两条接入路径之一。

## 决定

1. 两条正式接入路径，共享同一生成与烘焙核心（core/geometry/bake/recipes）：
   - **启动烘焙（默认）**：游戏在浏览器启动时直接调用配方烘焙，
     经 `adapters/canvas.js` 缓存为 Canvas 精灵；运行时只 `drawImage`。
     不强制导出 PNG/manifest。
   - **离线导出（可选部署）**：PNG 图集 + 版本化 manifest（ADR-0003），
     供压缩部署、跨工具消费或 Godot 等外部引擎使用。
2. `adapters/canvas.js` 是浏览器专用薄适配：只负责 painter/asset → Canvas
   与变体（镜像/白闪）缓存；不含游戏逻辑。其核心按 ADR-0001 保持可注入
   （Canvas 工厂由调用方提供），逻辑结构可在 Node 下用 stub 测试。
3. 静态纹理在启动时一次烘焙并缓存，运行时不得逐帧重新生成像素。
4. Godot 适配（`examples/godot/`）保留为按需读取的可选样例，
   不是安装、使用或首版验收的前提。

## 后果

- 模板与示例默认走路径 1；路径 2 由 `bin/pga.mjs export` 继续提供并维持测试。
- 两条路径的像素一致性由共享烘焙实现保证（画廊、导出、启动烘焙同源）。

## 备选方案（已否决）

- 只保留离线导出：违背原项目已被验证的零素材工作方式，也给网页 Agent
  增加不必要的构建步骤。
- 为浏览器重写一套烘焙器：直接违反"同源"约束。
