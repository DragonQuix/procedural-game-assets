# 对齐、标杆处理与宪章

本文件只给总控和 builder，不发给盲比阶段的 critic。

## 先看图再选路线

实际查看原图，记录尺寸、透明度、主体、风格、视角、光照、像素/线条语言和参考质量。
区分原生像素、缩放、压缩、抗锯齿与生成式像素风，不从显示尺寸推断逻辑分辨率。
先描述整体吸引力、气质和主次，再从形体组织、色块层级、材质概括与完成度分解质量依据。
说明何种视觉关系值得对标，不把角色特征或具体解法直接变成复制要求。
截图里看不到的背面、遮挡、动作过渡与帧时长不能自行说成已知。

先辨别用途：单资产、图标集、无缝地块、动画片段，还是展示板。概念板并非合规图集：
网格、透明度、画布、锚点、帧时长和动作连续性必须另定。不要机械切整板充当交付。

示例类型：大立绘旁有一组小角色和爆炸/弹体时，至少澄清要立绘、角色动画还是全套，
默认只追求同等质量；用户未明确的必要身份特征才需澄清。先用代表性关键帧验证方向，再扩展系列；
这不免除最后对所有约定动作与资产的复审。

## 只问影响结果的问题

- 默认质量标杆。是否另有必须保留的风格、功能或特征？未约束的部分允许原创，不重复询问已明确的意图。
- 交付范围、逻辑分辨率、实际显示大小、透明背景、方向/动作/帧数与节奏是什么？
- 程序化边界和导出格式是什么？有无可使用的参考纹理、依赖或收费服务授权？

已在用户输入明确的不要重复问。给出推荐默认值及其影响，集中对齐，不让填表代替看图。
当前绘制器无法表达关键特征时，先提出扩展方案/换路线；不能偷偷缩小分辨率或细节。

## 保存原图与派生参考

原图按字节只读保存并记录 SHA-256。允许无损裁切、统一背景、对齐和指定缩放的
派生参考时，记录原图哈希、crop 矩形、缩放算法、缩放倍数、背景色、输出哈希。
不超分美化、不补画缺失信息、不抹掉候选缺陷；所有派生处理均可重跑且不覆盖原图。
对照保持用途、主体显示尺度、信息量和显示算法可比；PNG 盲比画布须同尺寸，可留白，
不扭曲长宽比。原创设计不必同几何、同姿势或同构图；关键部位被视角遮挡时补等效视图。
不能过度缩小参考、包装候选或补画来制造公平。原图仍作为第二阶段的最高参照。

## 冻结宪章

运行目录写 `ALIGNMENT.md` 与 `charter.json`。后者可从 [宪章示例](../assets/charter.example.json)
复制，按真实任务填写。
在 `approval` 中引用用户确认或自主对齐授权的会话依据，不自造确认记录。

`visualPolicy` 分开质量标尺 `referenceProfile`、明确约束 `designConstraints`、原创空间
`creativeFreedom` 和必审范围 `scopes`。空约束数组表示没有额外特征要求，不补造身份约束。
在原图不足以支撑高质量目标或目标尺度时先澄清，不暗中降低标准或要求必须超越原图。

按 [视觉范围与准则](visual-quality.md) 为每个范围配置基础维度及适用的系列/动态/拼接
维度。每个视觉支柱绑定 `scopeId / dimension / basis / criterion`：有参考依据时设
`basis=reference` 并引用同范围的 `comparisonIds`，其他要求用 `basis=requirement`。
视觉不设 `minimum`，不能只写“好看”；交付支柱沿用 `minimum` 与真实复现证据。
整体美学另外必审，不是支柱分数平均。交付继续覆盖源码、格式、坐标、消费与文档。

固定 `captureProfile`：原生尺寸、显示尺寸、背景、相机或视角、姿态/帧序列、
种子、时间采样、采集命令；固定 `requiredGates`：本次真实适用的确定性、越界、
导出、锚点、消费等门禁。明确参考盲区、可接受原创范围和未覆盖项。
每个 scope 的 `views` 固定原生、显示及适用的播放/总览/拼接证据；`comparisons` 绑定
`scopeId` 与参考/候选 PNG 路径，覆盖能作可靠对照的资产与姿态。未支持的动作/背面等
按用户确认的独立标准或原创空间处理，不凭静态图臆造动态标杆。必要要求缺失才需补图或澄清。
视图、原图与派生处理记录全部进入冻结 evidence；参考材料列入 `referenceProfile.evidence`。

确认后保存原文与哈希。改范围/支柱/约束/质量依据/采集协议需用户重新同意并创建新候选，
旧 WOW 作历史记录。制作或评审代理均无权为了尽快结束而修改准出标准。
