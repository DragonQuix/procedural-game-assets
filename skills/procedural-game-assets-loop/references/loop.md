# 循环、隔离与恢复

总控维护 `checkpoint.json`，至少包括 runId、状态、授权依据、宪章哈希、当前候选、
批次列表、活跃执行者、待用户输入、下个动作、产物路径及已知费用。
默认预算字段为 null；这不是“运行到平台崩溃”的要求。

状态分别使用 `aligning / running / reviewing / completed / waiting_for_input /
capability_blocked / paused_by_user / cancelled_by_user / interrupted_by_host`。
只有最终双批次通过才是 completed。来图不能解除用户暂停；恢复时重新核对文件、
宪章与授权，确认原总控不再运行，避免双写。

## 每轮

1. 总控给独立 builder 的简报：当前差距、优先缺陷、一次可归因的修改假设、源码
   所有权、冻结的规格与采集方式、源码文档。明确“你不是唯一执行者，不得撤销他人
   修改”。工具包 CONTEXT 与 ADR 是边界来源，不发整个总控会话。
2. builder 优先处理导致整体或必需维度降档的关系，再处理支撑它的形色、动作与细节。
   保留最佳候选和应保护的优点，不按固定局部清单机械修复，不靠更多细节/噪声冒充质量。
   修改须落到源码/配方，不为了像标杆而抹去合格的原创选择；改完复看整体和关键状态。
3. 总控或中立采集者按冻结 profile 重建，不让 builder 只选好看的帧。所有约定资产、
   动作、显示尺寸都要覆盖；随机种子影响结果时采用对齐过的种子集合。
4. 技术预检：真实执行并记录命令、环境、退出码、输入/输出哈希。门禁失败先修，
   未评审不能记 NOT_YET，更不能记 WOW。缺图片或解码失败先修材料。
5. 停止写入候选目录，运行 `snapshot` 记录源码/交付与证据树。候选由真实文件、
   宪章与 profile 的哈希识别；更换任何文件均需新候选并重采证据。
6. 为当前批次派发独立 visual 与 delivery。visual 先封存两侧整体印象、相对质量与偏好，
   再揭盲全审。全部回收后按整体美学/等级差距/范围覆盖分诊，只把具体问题与证据给
   builder，不让 builder 跟 critic 辩论或修改裁决。下一轮重查全部范围，不只查返修点。
7. 首次全 WOW 后不改任何候选文件，另派全新上下文做完整复验，不告诉他们曾通过。
   两批次均有效才准出；复验 NOT_YET 则继续返修，禁止反复抽评审直到抽到 WOW。

## 材料与权限

| 角色/阶段 | 给什么 | 不给什么 |
|---|---|---|
| visual 盲比 | 中性 packetId、盲比任务书、匿名 A/B 图 | 原图来源、路径、宪章具体值、源码、历史、映射、其他 agent 提示 |
| visual 揭盲 | 已封存盲比、视觉准则、原图/派生记录、宪章、全部视图/动画、客观门禁、身份封套 | 源码、builder 叙事、历史分数、缺陷分诊 |
| delivery | 冻结源码/交付、依赖、README、宪章、客观门禁与身份封套 | 制作日志、自评、其他评审或历史成绩 |

阶段一只发 blind 目录，不发上级运行路径。封存其报告并记录哈希后才揭盲。
多对图用中性编号独立随机化，阶段一每一对均需记录；禁止只选择最好的对照。
所有角色只输出到各自报告目录，交付复现另建临时目录，不改冻结产物。

默认采用指令级约束：新上下文、只发白名单，并明确告诉 critic 不许读取其他目录、
源码（视觉席位）、制作历史、其他 critic 输出或来源映射。保存实际派发文本和宿主
上下文 ID；不要求操作系统沙箱、工具权限收缩或哨兵访问测试。共享目录本身不阻塞。
派发前检查材料文件名、PNG 元数据、旁边日志与自动注入的上下文是否主动泄题。
`fork_turns="none"` 只隔离聊天历史，`private/` 也不提供访问控制，报告不得夸大。
记录 `isolation.mode=instruction`、`status=recorded`，不是 verified 安全隔离。
如果实际发生越界读取或提前看到来源，记 contaminated、保留无效报告，重新派干净
上下文；没有独立子代理能力时才转交独立会话或记 capability_blocked。

## 返修不是随机重试

每个缺陷保留稳定 id、严重度、支柱、图中区域、应有/实际、复核方法和状态事件。
BLOCKER 是明确关键要求失败、关键功能不可用或证据失真；MAJOR 是实质质量降档或
不可交付；MINOR 是不影响已对齐质量和使用的局部瑕疵，须保留 nonBlockingReason。
身份差异只有违反用户明确约束才是缺陷；空泛“再高级一点”或个人喜好不能阻塞准出。
`NOT_COMPARABLE / UNVERIFIED` 先补证或澄清，不当成低质量开始无方向的重做。
更高追求单列可选建议，达到目标后不把“还能更好”作为继续循环的理由。

同一缺陷连续两轮无改善：重新测量、拆分根因、扩展配方/换实现方法，再继续；
不是停止上限。连续实验没有可归因收益时保留最佳结果，换假设，不靠换 critic 抽奖。
若根因是缺用户信息或当前路线根本不适建，精确报告并请求决策，不伪造能解决的承诺。
有反证可请全新 critic 一次复核争议项；复核不替代全量评审、不产生整包 WOW。

## 停止与收尾

尊重用户暂停/取消、宿主限制、外部工具硬停及授权边界。无预算上限不是自动授权
收费调用。能推进时继续；真正阻塞时保留产物、原始原因、差距与下一步。
只清理自己启动的进程和临时资源，不自动修改共享安装或独立试验项目。
阶段结束、上下文压缩或宿主中断都不是成功；不可承诺不存在的后台唤醒。
