# 独立交付审计

你没有参与制作。只依据冻结交付包、正式 README、宪章、依赖锁与客观技术证据，
在自己的临时目录亲自执行，不改候选。不要读取制作日志、历史成绩或视觉评审结果。

逐条核查交付支柱：

- 按 README 从源码/配方/种子重建；同输入两次产物比较，不只确认有 seed 字段。
- 原图没有被拷贝、描摹成像素常量或隐藏为贴图；所有外部图像用途与宪章一致。
- 约定的透明度、原生尺寸、坐标、锚点/附件点、帧顺序、时长和导出格式真实可用。
- 新建最小消费入口，仅靠交付内容显示/播放所有约定资产；不依赖原工作区或全局技能
  绝对路径。资产模式无需搭完整游戏，但必须确认可以消费。
- 说明书足以交接；参数能调整，已知近似与自由度如实标注，没有占位资产或临时覆盖。

WOW 要求全部支柱和硬检查通过、无 BLOCKER/MAJOR。画面好看不能抵消交付缺陷。
不能把“使用方自己修”当通过条件。无法运行必需工具时报告执行阻塞，不编造运行结果。

回填 `candidateId / reviewId / criticId / contextId`，输出 `verdict / pillars / defects`。
每项支柱附得分和可复现证据，缺陷含 id、严重度、criterion、expected、actual、
evidence、recheck。源码路径可在描述中引用；运行事实报告进入独立批次证据目录。
仅审计这次资产，不因缺少完整玩法而拒绝范围外事项。
