# 视觉评审改进方案：质量同级，不以复刻为目标

日期：2026-09-28。状态：普通版已实施为 0.4.1；循环版合同与任务书已实施为 0.5.0。

第 1–8 节记录循环版目标与实施方案，第 9 节记录普通版改造。循环合同现为 `pga-loop/2`，
最终字段以 `references/tooling.md` 与开发源校验器为准，长期取舍见 ADR-0007。
实现与结构测试不等于实际画面已达标，验证范围见 `../verification.md`；用户级安装另行升级。

## 1. 目标与边界

循环版生成的 2D 程序化资产，应在约定用途和审美方向内达到标杆的美术质量等级，
同时形成完整、自洽、有吸引力的原创设计。标杆提供质量标尺，不是待复制的答案。

同等级不要求相同角色、轮廓、配色、服饰、姿势、装饰或细节数量。用户明确要求保留的
特征另列为设计约束；不能从参考图中自动推导出这些约束，也不强制为区别而改变设计。

保留现行边界：独立 visual 与 delivery、先盲比封存再揭盲、指令级材料约束、同候选
连续两个完整批次 WOW、默认无轮数或预算上限。不增加默认评审席位，不扩大到 3D，
不要求为审资产搭完整游戏。普通版采用同一质量目标，但不继承此处的循环流程。

实施者必须以以下文档为术语、边界和架构决策来源：

- [CONTEXT.md](../../CONTEXT.md)：资产循环、候选、评审批次与模块边界。
- [当前路线](../PLAN.md)：循环版与普通网页游戏入口的产品边界。
- [ADR-0006](../adr/0006-asset-loop.md)：角色独立、双批次准出与工具能力边界。
- [ADR-0007](../adr/0007-quality-parity-review.md)：质量同级合同 v2、整体美学门禁与旧记录只读兼容。
- [ADR-0001](../adr/0001-platform-decoupling.md) 与 [ADR-0004](../adr/0004-web-first-integration.md)：纯核心、IO 分层与共享烘焙。
- [ADR-0005](../adr/0005-canvas-template.md)：轻量 Canvas 模板边界，不恢复完整游戏或 Godot 的必做要求。

当前没有 `CONTEXT-MAP.md`。本方案不重定义工具包坐标或生成接口。

## 2. 现有协议的具体缺口

| 位置 | 现状 | 改进方向 |
|---|---|---|
| `assets/charter.example.json` | 默认 `identity` 要求按标杆检查身份、轮廓与比例 | 改为设计质量和用户明确的设计约束，不默认检查身份相似度 |
| `references/alignment.md` | 已区分身份标杆与质量标杆，但没有独立的整体美学标准 | 将质量标杆设为默认，冻结质量依据、硬约束和原创空间 |
| `references/critic-blind.md` | 主要记录偏好、局部差异和来源猜测 | 先记录两侧整体印象，再判断完成度差距；偏好与等级分开 |
| `references/critic-visual.md` | 逐项 0–10 分，要求对应标杆区域 | 增加整体美学与质量同级裁决，允许比较不同设计的等效视觉功能 |
| `references/loop.md` | 返修优先轮廓和比例，缺陷示例含身份缺失 | 改为优先修复决定等级差距的问题；身份只在明确约束下适用 |
| `tools/asset-loop.mjs` | 校验分数、支柱、裁决、证据与双批次 | 增加必需的整体裁决和覆盖校验，不把数值达线当作美学证明 |

这些是协议覆盖缺口，不代表已经证实某次实际评审因此误判。

## 3. 对齐时分开定义三件事

| 项目 | 需要冻结的内容 | 不能混入的内容 |
|---|---|---|
| 质量标尺 | 标杆为何显得专业：形体组织、层级控制、色彩关系、完成度、整体吸引力等可见依据 | “必须长得像这张图” |
| 设计约束 | 用途、资产类型、显示尺寸、用户指定的风格/题材/功能与必要特征 | 从标杆自动继承的角色身份、调色板或装饰 |
| 原创空间 | 未被约束的造型、配色、姿态、材质表达和细节组织 | 以原创为由忽略用途、风格要求或质量差距 |

默认目标记为 `quality_parity`。用户没有指定复用特征时，身份相似度不计分，也不扣分。
风格是否必须接近需显式确定；即使要求同一风格，也只检查视觉语言，不要求复制具体设计。

制作前根据原图形成简短的质量标尺，记录其优势、可见短板、适用范围和无法证明的部分。
若标杆本身不足以支撑用户要求的高质量，或概念立绘与目标小尺寸精灵无法直接比较，
先对齐评价尺度或补充参考，不暗中降低标准，也不暗中把目标提高到“超过标杆”。

## 4. 评审范围

### 4.1 所有任务的基础范围

| 层次 | 评什么 | 主要证据 |
|---|---|---|
| 整体美学 | 完整画面是否有吸引力、统一气质、清晰主次和适度的视觉记忆点，是否显得成熟而非拼凑 | 正常显示尺寸的完整画面，先于局部检查 |
| 设计组织 | 轮廓、比例、姿态、体块与负空间是否共同表达功能和性格；不是与参考几何重合 | 完整主体，必要时辅以剪影或灰度诊断 |
| 色彩与视觉层级 | 明度/色相/饱和度关系、焦点、层次、疏密和留白是否受控 | 原色画面与约定背景 |
| 表现完成度 | 边缘、像素簇或线条、体积、材质、光影、细节是否干净、一致、恰当 | 原生尺寸与诊断放大图 |
| 游戏使用效果 | 实际使用尺寸下是否清楚、稳定，功能信息与视觉权重是否合适 | 目标显示尺寸、约定背景或最小使用场景 |

整体美学不是上述细项的算术平均。局部都正确但整体僵硬、散乱或缺乏吸引力，仍可不通过。
反之，简洁、克制的设计不因纹理少、颜色少或没有复杂光影而自动低于标杆。

### 4.2 按资产类型增加范围

| 资产类型 | 增补检查 | 不强加的要求 |
|---|---|---|
| 角色/生物 | 性格表达、姿态与重心、装备关系；多方向时的设计一致性 | 与标杆同脸、同衣服、同体型或同姿势 |
| 道具/图标 | 功能识别、视觉重量、图标集中的区分度与统一性 | 写实材质或复杂纹理 |
| 地形/地块 | 拼接后的整体效果、重复痕迹、边界过渡、前后景层次与可行走区域识别 | 只看单块漂亮，或强行套角色轮廓标准 |
| 特效 | 信息重点、形态演化、时序层级、强弱节奏、与主体的视觉关系 | 亮度更高、粒子更多即更好 |
| 动画 | 实际播放的节奏、重量感、动作意图、连续性与跨帧一致性 | 静态拼图代替播放，或用静态标杆臆测动作标准 |
| 系列/资产包 | 全套风格、尺度与完成度一致，关键资产没有明显低一档 | 用一张最佳展示图代表整套质量 |

宪章列明适用范围、每个范围的证据及不适用理由。所有约定资产和动作均需覆盖；
随机变体按事先冻结的代表性种子集合验证，不临时挑好看的样本，也不声称覆盖所有种子。

每个维度还须标明判据来源：标杆可直接支持的对照，或经对齐冻结的独立要求。例如只有
静态标杆时，动态质量按已确认的动作标准和实际播放验收，不宣称“动画已与静态图同级”。
缺少动画标杆不自动阻塞交付；缺少必要的动作要求或动态证据才需要补齐。

## 5. “同一等级”的评审准则

### 5.1 等级关系优先，数字仅作诊断

视觉评审使用以下相对等级，不采用总体相似度或加权总分决定通过：

| 关系 | 判断锚点 |
|---|---|
| `BELOW` | 存在影响整体观感、专业完成度或游戏使用的实质质量差距，需要设计或表现层面的返修 |
| `ON_PAR` | 在约定用途和方向内具备同档吸引力、设计控制力与完成度；允许风格选择和次要强弱不同 |
| `ABOVE` | 在达到同级要求的基础上有可说明的额外优势；不是必须追求的准出条件 |
| `NOT_COMPARABLE` | 尺度、材料、用途或参考覆盖不足，不能可靠作等级判断；先补材料或对齐，不盲目返修 |

对标杆能够支持的每个必需视觉维度及整体分别判断等级；独立要求维度分别给出满足、不满足
或证据不足的结论，不伪造标杆比较。核心维度不能以其他优点补偿明显降档，但不要求每个
局部都不弱于标杆；不影响等级的细微差异可以接受并说明理由。沿用的 0–10 分只作诊断，
不再用统一“9 分”代替质量同级判断。交付侧的技术标准不因本次美学改动而放宽。

### 5.2 整体美学的独立判断

critic 必须回答：在约定方向和用途下，这是否已是一件设计完整、处理成熟、值得采用的
正式资产？与标杆并列作为质量样本时，是否存在明显的档次落差？

整体评价关注形、色、节奏和重点之间的关系，允许证据指向整个主体或整个系列，
不强制把整体感受拆成像素缺陷。结论仍需说明看到了什么、为何影响整体效果。

“WOW”沿用为协议准出标签，表示达到约定的高质量，不要求每轮都制造惊奇，也不要求
华丽、写实、复杂或符合 critic 的个人口味。整体美学具有否决权，但不能成为无依据的
个人偏好否决权。

### 5.3 允许差异，不允许借差异降标

- 候选与标杆配色不同，但明度组织、焦点与协调度同档：属于允许差异。
- 候选纹理更少，但形体更清楚、材质概括自洽：不能仅因细节少扣为低一档。
- 候选服饰和轮廓不同，但功能、性格与辨识度成立：不报“身份不像标杆”。
- 候选很像标杆，但体块僵硬、颜色浑浊、重点分散：相似不能补偿质量不足。
- 单个角色很精致，但整套尺度、边缘语言或动画完成度不一致：整包不能由最佳项带过。

像素差分、SSIM、嵌入相似度、颜色数量、细节密度和“猜不出哪张是参考图”，均不作为
质量准出依据。技术回归可以使用像素差分，但必须与参考相似度评价分开。

### 5.4 返修意见的要求

问题至少包括：所属范围/维度、可见现象、对整体或使用的影响、标杆的质量依据、严重度、
证据及复查方法。可以指出整个画面的视觉关系，不必要求某个固定像素坐标。

合格示例：“候选头部与背包具有相同的最强明度对比，注意力被分散；标杆的主次控制更清楚。
需重新组织视觉重点，使目标显示尺寸下的主识别区域优先可读；不要求采用标杆的颜色。”

不合格示例：“再高级一点”“换成标杆的红色就好”“我更喜欢另一种风格”。

`BLOCKER` 对应关键约束失败、关键功能不可用或证据失真；`MAJOR` 对应实质质量降档或
明显影响使用；`MINOR` 对应不影响既定等级与用途的局部瑕疵。未经用户约定的身份差异
不是缺陷。可选的更高追求单列为建议，不作为继续循环的理由。

## 6. 评审流程和准出

1. **参考校准与冻结**：生成质量标尺、设计约束、原创空间及范围/证据矩阵，由用户确认
   或按已有自主对齐授权冻结。标准在看候选前确定，不能为结束循环而改。
2. **匿名整体初评**：阶段一先看完整图和正常尺寸，分别记录 A/B 的整体印象，再判断
   哪侧完成度更高、是否同档、哪些差异影响质量。偏好另记；不输出 WOW。
3. **封存后揭盲全审**：同一 visual 上下文读取宪章、原图和完整证据，检查全部适用范围，
   分别给整体美学、整体质量等级、各必需维度和设计约束结论。与盲比判断变化时解释原因。
4. **按影响返修**：优先解决导致降档的整体关系，再处理支持这些关系的局部问题。
   不把“增加细节”设为默认改进路径；builder 获得问题和验收效果，不被要求复制参考解法。
5. **原样独立复验**：第一次完整 WOW 后保持候选不变，另派全新上下文完成第二完整批次。
   任一批次失败按现行协议继续，不靠反复抽 critic 获取两次好评。

匿名材料中的来源猜测改为可选诊断，不再强制。偏好参考但认为两者同级是允许的；
偏好候选也不能自动证明高质量。阶段一只能评价看到的内容，不提前接收宪章中的身份信息。

对照优先保证用途、呈现条件和信息量可比，不要求不同原创设计具有相同几何或姿态。
保留原生与实际显示视图；不扭曲长宽比、补画、过度缩小参考，或用展示板包装掩盖资产缺陷。
放大、剪影、灰度等只作诊断。不同视角遮住关键内容时补等效评价视图，而不是强制模仿姿势。

视觉 WOW 必须同时满足：

- 整体美学明确通过，整体质量关系为 `ON_PAR` 或 `ABOVE`。
- 标杆支持的必需视觉维度达到同级要求；其余必需维度满足冻结的独立标准，明确设计约束
  满足，适用范围全部覆盖。
- 无 `BLOCKER`/`MAJOR`，所有 `MINOR` 均说明不影响目标等级，适用技术门禁通过。

最终仍须 visual 与 delivery 同时通过，并取得同一冻结候选连续两个有效完整批次的 WOW。
材料不足、污染或无法读图不算低质量裁决，更不能算通过；先补证、重新派发或记录真实阻塞。
两个批次是现有流程的复核要求，不宣称统计学证明或客观美学测量。

## 7. 落地改动

### 7.1 技能与模板

- `SKILL.md`：明确质量同级、非复制目标，增加整体美学独立门槛。
- `references/alignment.md` 与 `assets/charter.example.json`：加入质量标尺、明确约束、原创
  空间和适用范围；移除默认身份相似度支柱。
- 新增 `references/visual-quality.md`：集中维护第 4、5 节的范围与判据，供总控和揭盲 critic
  按需读取；盲比任务书只包含无身份的整体观察与相对完成度说明。
- `references/critic-blind.md`：整体先行，分开偏好与质量关系，取消强制猜来源。
- `references/critic-visual.md`：全范围检查、整体裁决、同级判据、可接受差异与返修证据。
- `references/loop.md`：按等级差距分诊，调整身份缺陷定义；保留暂停、恢复和反抽奖规则。
- `references/tooling.md`：同步字段、准出校验与兼容说明。交付 critic 的独立性和实测要求不变。

### 7.2 结构化合同与兼容

本次改变默认目标和视觉必填裁决，已采用 `pga-loop/2`，不把语义变化静默塞进旧合同。
只增加能够约束评审行为的字段，具体结构与任务书、示例及校验器同步：

| 位置 | 最小信息 |
|---|---|
| 宪章 | `visualPolicy.goal=quality_parity`、质量标尺、明确约束、原创空间、必需范围/维度、判据来源及证据映射 |
| 盲比报告 | A/B 整体印象、相对完成度、偏好及理由、可见差异；来源猜测可选 |
| 视觉报告 | `holistic.aestheticVerdict / holistic.qualityRelation`、各维度同级或独立要求结论、`coverage / constraints / blindReconciliation`、缺陷与证据 |

`tools/asset-loop.mjs` 只检查必填信息、枚举、覆盖、裁决一致性、证据路径/哈希及双批次。
整体 `BELOW`、未评估的必需范围或必需维度失败，不能被高分或顶层 `WOW` 绕过。
分数保留为视觉诊断数据，不参与加权放行；脚本不从像素、描述或分数自动推断审美。

旧 `pga-loop/1` 记录保留历史身份，不自动补“整体已通过”或迁移旧 WOW。进行中的旧任务
若升级，应确认新宪章、生成新候选并重新评审；不覆盖旧记录。升级前明确提示旧合同与
新工具不兼容，旧记录的读取/验证方式与旧工具版本随发行说明固定。

在 `CONTEXT.md` 补充“质量同级”与“设计约束”的长期术语，新增 ADR-0007 承接 ADR-0006，
记录本次合同演进及历史证据兼容取舍。历史验证器位于 `tools/legacy/asset-loop-v1.mjs`。
所有工具改动先落开发源，再由发行脚本生成载荷，不手改技能中的派生工具包。

## 8. 验证与实施顺序

先改判据与示例，再改结构化合同和验证器，最后发行。避免只改文案而机器仍允许旧条件通过。

| 阶段 | 工作 | 完成条件 |
|---|---|---|
| 1. 判据定稿 | 术语、范围矩阵、同级定义、原创边界、critic 任务书与宪章示例 | 不再默认奖励相似度；整体美学与质量同级均有明确结论 |
| 2. 合同实现 | `tools/asset-loop.mjs`、`tests/unit/asset-loop.test.js`、工具合同 | 缺整体裁决、核心维度低档、漏覆盖和旧合同混用均不能通过 |
| 3. 独立小样本验证 | 用预先校准的真实图或可复现资产评审，不向 critic 提供预期结论 | 能区分风格差异与质量差距，返修意见不把候选推向复制 |
| 4. 发行安装 | `tests/integration/loop-release.test.js`、发行校验、循环版升级与既有入口核验 | 源码/载荷一致，不覆盖普通版自己的流程；如用户授权升级，再更新共享安装 |

本次已完成合同实现、结构测试和项目内发行；独立前向测试只覆盖启动、看图、对齐及
多范围宪章填写。第 3 阶段的校准实图评审对照尚未执行，第 4 阶段未更新各宿主安装；
不把宪章可用性或合成报告校验当作实际美术判断的实证。

结构测试至少覆盖：顶层 WOW 但整体 BELOW、细项达分但整体美学未通过、必需范围漏评、
证据不足、视觉与交付缺任一席、只通过一个批次、候选变更或复用旧批次，以及旧报告无法
冒充新合同。合成报告只用于结构测试，不当作视觉质量实证。

行为验证重点使用下列对照情形，判断依据需预先校准，不能由实施者随意给图片贴等级标签：

- 造型与配色明显不同，但设计控制力和完成度同档：不得因不像而否决。
- 外观高度相似，但整体生硬、层级失控或表现粗糙：不得因相似而放行。
- 细项缺陷很少，整体却分散或平庸：应能指出整体差距。
- 克制简洁与丰富细节两种设计均专业：不能默认细节多的一方等级更高。
- 单张精致但整套/动画掉档，或只在夸张放大下好看：不能漏过使用与系列范围。
- 参考缺少动态证据或条件不可比：应报告局限；动画可按已冻结的独立要求验收，不伪造
  参考标准，不因缺动画标杆而要求无方向地继续循环。

采用能回答上述关键问题的最小验证，不为填满报告启动完整无限生成实验。样本验证只能
支持本次协议改进，不能宣称所有模型、题材和宿主具有稳定一致的审美判断。

## 9. 普通版的审查与改造

用户新增范围为原 `procedural-game-assets` 技能。它仍服务网页游戏制作，不升级为默认
无限循环。术语与边界沿用本方案开头列明的 CONTEXT 与 ADR，具体标准落在开发源
`docs/visual-quality.md`，由发行脚本携带，供技能和干净目录中的游戏共同使用。

| 审查发现 | 实施改动 |
|---|---|
| 切片验收重功能与可读性，缺少独立整体美学结论 | 入口与验收加入整体美学、标杆同级和完整游戏画面的判断 |
| 诊断参考建议总分 ≥10/12 即可批量派生 | 移除总分放行；整体与必需维度不得相互抵消 |
| 固定从轮廓开始修，容易忽略整场景的形色关系 | 先整体再局部，按影响排序，修改后回查全局与关键状态 |
| 未清楚区分参考质量和角色身份 | 明确质量标尺、设计约束、原创空间；不奖励复制，不惩罚允许差异 |
| 未明确无标杆、静态标杆或不可比材料的处理 | 无标杆按独立目标；静态参考不裁决动作质量，必要证据缺失明确记未验证 |
| 画廊诊断不能代表完整游戏质量 | 增加场景、HUD、系列、关键交互和实际尺寸检查，不扩大单资产任务 |

普通版记录 `PASS / NOT_YET / UNVERIFIED`，有对照依据时再记录质量等级关系，不强制
独立子代理、盲比、宪章 JSON 或双批次。不把普通版自审改称独立 WOW。

普通版改造版本为 0.4.1，当时仅重建普通版技能载荷。本次循环版升级为 0.5.0，普通版
发行副本不重建；两版的用户级已安装内容都未在本次合同改造中自动升级。
验证重点是标准与入口自包含、复制后链接可读、发行清单和现有功能回归。新增
`tests/integration/skill-release.test.js` 只验证携带与链接，不冒充美学或 agent 行为测试。
实际验证及未覆盖项写入 `docs/verification.md`，用户级升级另按用户授权执行。
