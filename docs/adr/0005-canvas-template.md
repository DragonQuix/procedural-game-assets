# ADR-0005：轻量 Canvas 网页游戏模板——范围与测试接口

日期：2026-09-26。状态：已接受。

## 背景

范围校正后的首版验收是"干净目录做出可玩网页游戏切片"。资产工具包只解决美术；
切片还需要最低限度的游戏骨架。约束是不能长成通用引擎，也不照搬原游戏的
战斗与关卡。

## 决定

1. 模板即 `examples/canvas-slice/` 的升级形态（不另起重复模板），提供且仅提供：
   固定步长循环（累加器）、键盘输入、暂停与重启；
   精灵动画（清单毫秒时长）、镜头（跟随卷轴）、AABB 分轴碰撞与一种交互（射击命中）；
   场景 / 自发光 / HUD 层序，最小粒子与受击白闪反馈；
   本地静态预览与运行说明。
2. **逻辑层无 DOM**：`template/logic/` 只依赖显式输入与种子（core/rng），
   可在 `node --test` 全量验证；表现层（`template/render/`）经
   `adapters/canvas.js` 消费启动烘焙的精灵。
3. **测试接口**：`createGame({ seed, ... })` 返回可手动推进的对象：
   `step(n, input)` 逐帧推进、`state()` 读取可断言快照、`setPaused()`；
   同种子同输入序列必得同状态。自动化测试（含浏览器 smoke）不依赖手感。
4. 模板数据（关卡块、敌人表、手感参数）是普通 JS 数据，改游戏 = 改数据；
   不内置关卡编辑器、物理引擎、音频、存档、网络。

## 后果

- 首版验收的可玩切片以此模板 + 新配方资产完成。
- 模板不属于资产核心库；它消费核心，是"怎么用"的参考答案，不是框架锁定。

## 备选方案（已否决）

- 移植原游戏循环/导演系统：超出"最低必要"，且会把模板块死成那一个游戏。
- 用现成引擎（Phaser 等）：引入大依赖，违背零素材可教学的目标。
