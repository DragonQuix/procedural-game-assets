# ADR-0009：Studio 编辑事务——候选、保护与本地工作区存储

日期：2026-09-28。状态：已接受（M2 范围）。

## 背景

ADR-0008 建立了"文档 → 渲染 → 导出"的只读管线。M2 要打通真正的编辑闭环：
agent 对指定部件做有限修改、比较少量候选、接受或回退，且失败绝不能污染已确认版本。
关键约束来自 `docs/PGA_STUDIO_IMPLEMENTATION_HANDOFF.md` §6–§7：
候选默认不改变 head；保护区域由操作计划**独立计算**；请求可幂等重试。

## 决定

1. **操作即数据**：三个有限操作（`geometry.set`/`material.set`/`ramp.set`）是纯函数
   `applyOperation(doc, operation) → { doc', plan }`（`src/studio/operators.js`）。
   plan 记录目标节点与逐字段旧/新值，是后续一切检查的输入；文档不含可执行内容的前提不变。
2. **保护检查独立复核**（`src/studio/protect.js`）：
   - 结构：非目标节点与资产级字段（seed/canvas/style/anchor/attachments）逐字段不变；
     目标节点只许 plan 声明的字段变。
   - 像素：允许影响区域 = （旧几何 ∪ 新几何，几何操作外扩 1px 描边邻域）**减去**
     未变更高层节点的支持掩码遮挡；全量重渲染后逐像素差分，区域外变化即违规。
     声明的像素保护区域（如 `terminal.screen`）逐一单独核对。
   - 元数据：锚点/附件点/帧尺寸按声明核对。
   - 修改本身受像素/结构保护的目标节点 → 前置 `CONSTRAINT_CONFLICT`（不经渲染）；
     其余违规 → `CANDIDATE_INVALID`。允许影响区域绝不从事后差分反推。
   - 编译器为每个节点输出支持掩码（内画布坐标），像素绘制与遮挡计算同源。
3. **本地单写者工作区**（`src/adapters/studio-store.js`）：
   - 不可变修订 `revisions/rN.json` 与未提交候选 `candidates/c-*.json` 先写完整
     （临时文件 `*.tmp-<pid>-<n>` + 原子替换），`head.json` 最后更新；
     崩溃残留可识别（state 列出），不自动删除任何文件。
   - 单写者锁 `lock`（pid）；持锁进程死亡后允许接管；活锁占用返回
     `WORKSPACE_BUSY`（retryable）。并发安全底线是 commit 的 `expectedHead` 校验，
     不是锁本身。
   - 候选 ID = 基准 + 操作 + 保护项的内容哈希（确定性，天然去重）；候选默认保留为证据，
     提交与否都不抹除。渲染相同的候选标注 `duplicateOf`/`UNCHANGED`，不凑"多样性"。
   - **commit 不信任落盘的检查结果**：接受时用基准＋操作重新推导文档、重编译、
     重新执行保护检查，三者（哈希、推导文档、检查状态）与落盘记录不符即视为篡改拒绝。
   - 恢复 = 创建引用旧文档内容的新修订（历史 ID ≠ 内容哈希），不抹除历史。
   - 幂等台账 `requests/<id>.json` 落盘：同 requestId 同内容重试返回同一结果；
     同 requestId 不同内容报 `REQUEST_ID_CONFLICT`；重启后仍有效。
4. **CLI 沿用同一实现**：`bin/pga-studio.mjs` 增加 state/edit/explore/commit 与
   工作区模式的 inspect/export；新增退出码 6（版本/请求冲突）、7（工作区占用）。
   编辑逻辑不进 CLI，避免三份实现。
5. **本轮不做**：任意跨版本合并、多写者协同、分布式存储、脏矩形增量渲染
   （图像很小，全量重渲染足够）、MCP 适配（M3）。

## 后果

- "创建 → 看图 → 探索 → 拒绝非法候选 → 接受 → 恢复 → 哈希验证 → 导出"可真实运行，
  篡改、过期、重放、崩溃残留均有测试证据（`tests/integration/studio-m2.test.js`）。
- 候选与历史只属于 Studio 工作区，不进入游戏运行时帧结构与对外 manifest。
- 后续阶段（多帧、风格包）必须沿用同一事务与保护语义，不得绕开 protect 出图。

## 备选方案（已否决）

- **信任候选落盘的检查状态**：候选文件可被手改；commit 必须重新校验，否则保护形同虚设。
- **用文件锁作为唯一并发保证**：锁有死亡残留与竞态；`expectedHead` + 原子 head 替换
  才是正确性底线，锁只作单写者便利与友好报错。
- **就地修改 head 指向旧修订实现"恢复"**：抹除历史，违反可追溯要求。
- **允许区域 = 实际差分集合**：循环论证，任何破坏都会被判合法（HANDOFF §7.4 明文禁止）。
